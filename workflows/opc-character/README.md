# 虚构角色创建工作流（OPC 朋友）

给一个**虚构的新角色**做出一整套形象：三视图 → 头像 → 生活照，画风与 Alice 的 OPC 朋友统一。

> 适用范围：新造的虚构角色。Alice 与洛小山这两位**正典角色不走这里**，
> 仍按 `docs/垫图逻辑.md` 和 `.cursor/rules/brand-image-gen.mdc` 执行。

本工作流来自 Alice 十三位内置朋友的实际生产（2026-09 至 10 月），中间被用户退回过多次，
下面「踩过的坑」一节把每次退回的原因都固化成了规则。
成品范例（十三位已有角色的人设、三视图、头像、生活照和 `spec.json`）见 [`refs/alice_friends/`](../../refs/alice_friends/README.md)，可以直接拿其中的 `spec.json` 当写法参考。

## 一张图看懂

```text
人设（文字）
   │  你写，或让 AI 按示例补全
   ▼
spec.json ──► build_prompts.py ──► sheet.txt / avatar.txt / life.txt
                                      │
   ┌──────────────────────────────────┘
   ▼
① 三视图   只用文字，1536x1024，纯白底 + 三个全身角度 + 六个表情     → 挑一张定稿
② 头像     只垫定稿的那一张三视图，1024x1024，一次出 2 张候选       → 挑一张
③ 生活照   只垫定稿的那一张三视图，1024x1536，出 1 到 2 张候选      → 挑一张
   │
   ▼
review_page.py 排成一页并排挑选 → 定稿归档
```

## 快速开始

```bash
cd workflows/opc-character
pip install httpx                       # 唯一依赖，仅 gen_image.py 用到

# 1) 复制示例，改成你的角色（字段说明见下）
mkdir -p my_character && cp examples/spec.example.json my_character/spec.json

# 2) 生成三份提示词
python3 build_prompts.py my_character   # → sheet.txt / avatar.txt / life.txt

# 3) 配 KEY（见下一节），然后出图
cp .env.example .env                    # 填入你自己的 MIYANG_API_KEY
python3 gen_image.py --prompt my_character/sheet.txt --size 1536x1024 --count 2 --out my_character/sheet_v1.png
#   看图，挑出一张最好的，比如 sheet_v1a.png

python3 gen_image.py --prompt my_character/avatar.txt --size 1024x1024 --count 2 \
  --ref my_character/sheet_v1a.png --out my_character/avatar_v1.png
python3 gen_image.py --prompt my_character/life.txt --size 1024x1536 \
  --ref my_character/sheet_v1a.png --out my_character/life_v1.png

# 4) 并排挑选
python3 review_page.py my_character     # 打开 my_character/review.html
```

产出建议归档到 `outputs/{日期}_opc_{英文名}_虚构角色{中文名}/`，与仓库其他产出保持一致（见 `docs/垫图逻辑.md` 第六节）。

## 生图服务：用米羊网关，KEY 由你自己填

`gen_image.py` 默认走**米羊网关**，模型 `miyang/image-1`，地址 `https://miyang.cn/api/v1`。

- **仓库里没有任何 KEY**。`.env.example` 里 `MIYANG_API_KEY=` 是空的，需要你自己去
  <https://miyang.cn/console/keys> 创建一把，复制 `.env.example` 为 `.env` 再填进去。
- 也可以不写文件，直接 `export MIYANG_API_KEY=...`（环境变量优先于 `.env`）。
- `.env` 已在仓库 `.gitignore` 里，不会被提交。**不要把 KEY 写进提示词、`.prompt.json` 或任何存档。**
- 网关对同一把 KEY 大约支持 3 路并发，脚本已限制为 3，遇到 429 会自动退避重试。
- 可用环境变量覆盖：`MIYANG_BASE_URL`、`MIYANG_IMAGE_MODEL`。

### 换一个生图工具

这套工作流真正有价值的是**提示词**（`build_prompts.py` 的输出）和**出图顺序**，不是某个特定服务。
你可以用任何生图工具，包括：

- **Codex 默认的生图工具**
- **Cursor 的生图工具（GenerateImage）**
- 其他任何支持「文生图」和「参考图 + 提示词」的工具

做法：把 `sheet.txt` / `avatar.txt` / `life.txt` 的全文作为提示词，按下面的约定喂给工具即可。

| 步骤 | 提示词 | 参考图 | 尺寸 |
|---|---|---|---|
| 三视图 | `sheet.txt` | 不用 | 约 3:2 横版（1536x1024） |
| 头像 | `avatar.txt` | **只给选定的那一张三视图** | 1:1（1024x1024） |
| 生活照 | `life.txt` | **只给选定的那一张三视图** | 2:3 竖版（1024x1536） |

工具如果只能选比例、不能指定像素，选最接近的比例就行。参考图的作用只是锁定脸型和体型，
提示词里已经写明「不要照搬参考图的姿势、视线和表情，服装按文字描述」。

## spec.json 字段

照 `examples/spec.example.json` 填。**所有「类似 #xxxxxx」的色值和具体物件都要写**，空泛描述会让整体越画越灰。

| 字段 | 写什么 |
|---|---|
| `name` | 角色名 |
| `gaze` | 头像朝向：`front` 正脸直视镜头 / `left` 脸转向画面左 / `right` 脸转向画面右 |
| `sheet_person` | 三视图用的外貌：年龄、脸型、五官特征、发型发色、肤色、体型。要写头身比（约 1 比 6.5）和「脖子长度粗细正常」 |
| `skin_hair` | 肤色和发色的具体色值，并写「脸颊、耳廓、鼻头有淡淡的红晕，有血色不苍白」 |
| `avatar_person` | 头像里的外貌加服装（逐件写颜色和款式） |
| `avatar_expression` | 神情，一句话。**不要写视线方向**，视线由 `gaze` 控制 |
| `avatar_pose` | 一个符合场景的肢体动作（坐着、手放桌面、捧饮品、抱臂、拿书或手机、挎包等） |
| `avatar_scene` | 大景深的清晰真实地点，写出具体景物和光线，避开雕像、头像类地标 |
| `avatar_color` | 色彩说明：每个主要景物和服装的颜色，结尾写「鲜活明亮、层次丰富，而不是发灰发白」 |
| `life_person` `life_scene` `life_action` `life_action_text` `life_light` | 生活照的人物、场景、**确定的单一动作**、光线 |

朝向建议按性格分配，并让整批角色**混搭**，不要全是同一个方向：沉稳外向的正脸，安静出神的偏左，好奇观察型的偏右。

## 提示词结构（`build_prompts.py` 已实现）

`画风段` → `画面描述` → `【本张必须使用的人物动作：…】` → `参考图说明（只定脸型体型）` → `解剖硬约束`

- 画风段是 `style_anchor.zh-CN.txt` 的原文，**一字不改**，这是整批角色画风统一的锚。
- 头像只把画风段里「眼神与场景互动，不要空洞地直视镜头」这一句按 `gaze` 替换，其余不动；生活照保留原句。
- 头像和生活照**只垫选定的一张三视图**，不要再垫别的图，更不要把上一轮成图当参考。

## 踩过的坑（每条都对应一次被退回）

1. **所有人都朝右上角看**。画风段那句「不要空洞地直视镜头」是给朋友圈场景照写的，头像沿用后被理解成「不许看镜头」；
   表情里再写「视线看向画面外」，只有「外」没有方向和高度，模型统一落在右上。
   → 头像单独写视线：正脸写「直视镜头」，侧脸写「平视看向画面左或右侧远处，不看镜头、不向上看、不仰头」。
2. **全改成正脸又像证件照**。→ 朝向混搭，并给每个人一个肢体动作。
3. **改成半身像被否决**。头像是名片，必须胸部以上、脸占大头。→ 胸像构图，动作靠肩膀、前臂和手在画面下缘表现。
4. **动作全是「扶栏杆」，模型在人物前方硬加栏杆**。→ 动作要多样（坐、手放桌面、捧饮品、抱臂、拿小物件、挎包），
   并且**提示词里不要出现「栏杆」二字**，写出来反而诱导模型去画；另写「画面前方不要出现多余的前景物体」。
5. **三视图里的「手托下巴思考」表情被头像模仿**，头像里人就托着下巴。→ 三视图表情不要这个，六个表情视线都朝镜头。
6. **某个角色画风和其他人不一致**（纯白背景、更锐利的平涂、肤色偏黄）。→ 定稿前和其余角色并排对比；
   头像背景一律用大景深的清晰水彩场景，不要纯白底。
7. **整体越画越灰**。→ 肤色、发色、每件衣服都写具体色值；三视图写头身比和脖子正常，否则头偏小。
8. **背景虚化**。→ 写「背景不是虚化背景，而是大景深的清晰场景」。
9. **场景里出现雕像、头像类地标**。→ 场景描述里写明「不要出现任何雕像、头像或人物雕塑」，并避开这类地标。
10. **名册墙和详情页不是同一张图**。→ 同一个角色，外面卡片和里面详情默认展示的必须是同一张肖像，日常照放在第二个标签。
11. **图换了线上还是旧的**。图片带版本号缓存，换图后版本号要加一，且必须**上传之后**再加，提前加会把旧图缓存在新版本号下。
    页面本身也可能被缓存，换图后让用户刷新一次。

## 挑图标准

- 三视图：三个角度脸型、发型、体型一致；六个表情视线朝镜头；服装只有基础白 T 和深灰长裤；没有多手多指。
- 头像：脸清晰、胸像构图、视线符合 `gaze`、画风与同批其他角色一致、背景是清晰的真实场景。
- 生活照：动作是确定的单一动作、场景可辨认、色彩鲜活。
- 任何一张出现多手、多臂、畸变、乱码或水印，直接废弃重出，不要后期硬修。

## 文件

| 文件 | 作用 |
|---|---|
| `build_prompts.py` | 从 `spec.json` 生成三份提示词 |
| `style_anchor.zh-CN.txt` | 统一画风段（`{{NAME}}` 会替换成角色名），一字不改 |
| `gen_image.py` | 米羊网关出图，支持垫图、一次出多张、3 路并发和重试 |
| `review_page.py` | 把候选图排成一页并排挑选 |
| `examples/spec.example.json` | 虚构角色示例 |
| `.env.example` | KEY 留空模板 |

# Alice 二创垫图逻辑

覆盖两位角色：**Alice** 与 **洛小山**（狐狸吉祥物）。品牌 Logo 仅作排版素材。
体系来自米羊品牌视觉仓库的实战沉淀，本文是本仓库唯一的垫图规范。

---

## 一、总原则

1. **一次成图**：每次都从本仓库 `refs/` 的正典参考图出发，一步生成最终画面。禁止把生成结果当下一次的参考图，细节会代代劣化
2. **参考图管人，提示词管画面**：模型对参考图的服从不完全，关键外貌必须在提示词里显式声明为「身份锁」，否则会被缺省描述覆盖（实战教训：参考图是长发，提示词没写就出了短发）
3. **参考图职责分离**：每张参考只承担一种职责，提示词逐张说明取什么、禁止取什么
4. **主生成默认只用 Cursor 自带生图工具（GenerateImage）做 Image 2.5 垫图**，参考图走 `reference_image_paths`；局部修补可用 Gemini，主体不许换工具重出。没有 Cursor 内置生图、或需要 4K 时用米羊网关（标准档 `miyang/image-1`、高清档 `miyang/image-hd`），通道选择与 KEY 流程见第十一节
5. **逐图存档**：每张产出配同名 `.prompt.json`，逐字保存提示词与参考清单
6. **先读原文再动笔**：各角色的历史资产几乎都带同名 `.prompt.json` 原始提示词。写新提示词前，必须先找相近场景 / 相近资产的原文读一遍，身份锁段落沿用原文措辞，场景部分参考其结构。信息宁多勿少，不许凭记忆重新发明

## 二、参考图职责（Reference Roles）

| 职责 | 取什么 | 禁止取什么 |
|---|---|---|
| parent_fullbody | 身高比例、全身剪影、服装形色、衣料垂落 | 不许用表内小脸格重定义五官；不跟随格子排版与白底 |
| parent_detail | 脸与五官、发型发色、挑染位置、耳周处理、妆容强度 | 不取其全身比例；非严格侧面时保持其头发遮挡关系 |
| style_anchor | 渲染技法、线条性格、着色方式、写实程度、光温、饱和水平 | **绝不拷贝其中的人物、脸、发型、首饰、服装、姿势、背景** |
| jewelry_spec | 首饰的形状、数量、颜色、比例（按实际佩戴缩小） | 无权撩开头发露出被 detail 遮住的耳朵；不跟随构图背景 |

所有参考图的构图与背景一律不跟随，构图只听提示词。

## 五、提示词写法

按顺序组织：画风声明 → 场景与光线 → 构图规格 → 逐角色身份锁 + 当次动作 → 参考图职责逐张声明 → 红线规则。

### 构图用百分比规格

不写「半身、留点空」这类模糊话，写硬数字。例（竖版半身卡）：

> 头顶在画面高度 10%-14%，腰线 92%-96%，脸高为画面高度的 24%-28%，双肩与肘上完整入画；头顶与两肩外侧各留 ≥7% 画宽的安全边距；人物水平居中；相机平视不俯不仰。

场景图同理：写明人物占比、地平线位置、留白区（如右侧开门遮挡区 15%-20% 无主体）。

### 颜色与光影纪律（写进提示词）

- 阴影带色不死黑，但与受光面一眼可分；最亮与最暗之间要有足够跨度，画面不许整体发白发灰
- 天空是有颜色有层次的面，再淡也要留蓝调，禁止纸白
- 肤色发色保留光的暖意（活血色的暖杏色皮肤），暖度以风格锚点为上限，不许更黄更橙
- 降饱和指令只作用于背景（大面积绿植降为带灰的沉稳绿），人物肤发不受影响
- 禁止全画面棕褐 / 复古滤镜、荧光绿、刺眼原色

### 动作与手部避坑（Alice 项目实战教训）

- 复合动作（转身 + 挽手 + 伸手）极易画错方向、长出多余手臂，拆成原子动作
- **手心朝镜头的张开手掌几乎必翻车**（海星手）；给模型自由（whatever hand position is most natural）或选稳妥姿势（放松下垂、侧掌托举、握物）
- 反物理姿势画不出正常的手，先想真人能否做到
- 表情写具体（bright attentive eyes, bright open-tooth smile），别只写 happy

### 红线规则（每次必带）

- `Limb count absolute rule: each character has exactly two arms and two legs, no extra limbs anywhere.`
- `faces crisp and individually recognizable`（多人时人人可辨认）
- `NO text anywhere, no letters, no logos, no watermark, no UI elements, no frame lines`
- 注意：这条红线只在「无字底图 + 代码后排版」方式下带。成品需要文字时按第九节问用户选文字处理方式，选「生图直出文字」时本条替换为逐字列出的文字清单

## 六、逐图存档与版本纪律

### 目录结构：按「日期 + 事项」分批次归档

产出**一律不许平铺在 `outputs/` 根目录**（教训：曾平铺到 84 个文件，找图、判断版本关系、辨认哪张是成品全靠猜文件名）。每次需求开一个批次目录：

```
outputs/{YYYY-MM-DD}_{en_slug}_{中文事项名}/
```

- 日期取**该批次第一张图的生成日期**，跨天继续做同一事项不改目录名、不新建目录
- `en_slug` 与图片文件名里的 `{kind}` 同源（如 `national_day_splash`、`mid_autumn_moon_rabbit`、`terrace_study`），保证脚本与文件名口径一致
- 中文事项名是给人看的，写清楚这批图是干什么的（如 `国庆开屏`、`Alice中秋赏月`、`Alice与洛小山露台共学`）
- 例：`outputs/2026-10-01_national_day_splash_Alice国庆开屏/`

分批规则：

- **同一事项的后续版本回原批次目录**：v2、v3 与被替代的 v1 必须放在一起，否则版本链断裂、`supersedes` 字段无从对照
- **同一天的不同事项各开一个目录**，不合并
- 一个批次内多角色、多形态（底图 + 海报 + 表情包）不再拆子目录，靠文件名区分
- 目录**永不删除、永不改名**（改名会打断已有引用与 git 历史）

引用纪律：

- 目录名含中文，在 HTML / Markdown 链接里用 URL 编码（`国庆开屏` 要写成 `%E5%9B%BD%E5%BA%86%E5%BC%80%E5%B1%8F`），在 shell 命令里一律加引号
- 移动或新建批次目录后，必须回查并同步 `README.md`、`scripts/*.py`、本文档里的存档路径引用，不许留失效链接
- 交付给用户时给**完整相对路径**（含批次目录），不要只给文件名

### 单图命名与字段

- 产出命名 `{character}_{kind}_v{n}.png`，旁放同名 `.prompt.json`
- 字段：`version / character / kind / status / provider / generation_language（zh|ko|en，按第四节的 IP 语言锁）/ prompt（实际调用的逐字原文）/ reference_image_paths / reference_roles / requested_aspect_ratio / actual_size / 审计结论 / approved_at / user_judgement_zh`；需要时可附 `prompt_en` / `prompt_zh` 作归档对照，实际调用只用该 IP 的指定语言版本

## 九、带文字物料工作流（海报 / 说明卡 / 邀请函）

1. **判定成品形态**：需求里出现规则说明、联系人、流程、标语等功能性信息 → 成品是平面海报，不是场景插画
2. **文字处理方式，默认 A，选 B 需用户点名**：

| 方式 | 适用 | 特点与风险 |
|---|---|---|
| **A. 生图直出文字**（Image2 / Cursor 内置生图，**默认**） | 绝大多数海报、标题、短句、艺术字 | Image2 的文字渲染效果好，字体气质、颜色、装饰会自然融进画风，整体感远胜后贴。提示词里逐字列出每一句要写的文字、指定语言即可，字体风格交给模型发挥；交付前逐字核对，出错字重生成 |
| **B. 无字底图 + 代码后排版**（仅用户明确要求时） | 文字必须绝对准确且文案会频繁改（如负责人换人）的维护型物料 | 文字准确、改文案只需重跑脚本；**但代码排的字是「系统字体贴上去」的感觉，与手绘画风脱节，容易显素显丑**（早期海报教训）。选 B 就要接受这个观感代价，且排版要取画面色、控制字号层级 |

红线 `NO text` 只在方式 B 的底图提示词里带。

**方式 A 只锁两件事，其余放开**（经验出处：国庆开屏 v3，存档 `outputs/2026-10-01_national_day_splash_Alice国庆开屏/alice_national_day_splash_v3.prompt.json`）：

- **锁文案**：提示词里每段文字用「必须准确写出“XXX”」逐字锁定，交付前逐字核对
- **锁道具唯一性**：关键道具写唯一性约束（如「全图仅一扇门、一个门把手，禁止独立门把图标」），防止模型把道具复制成散落图标
- **不锁文字风格与版面创意**：字体气质、文字载体形式、配色、动势、构图交给模型每次自由发挥，禁止把某一次的成功样式（如手绘字 / 缎带 / 贴纸章）写死成模板——每次生成都应该长得不一样
- 角色正典逐字原文（画风锚定、外貌、后缀）照常带上，与自由发挥的版面并不冲突，身份不会丢

3. **底图 / 画面提示词直接描述「品牌平面设计」**：非对称编辑构图、有机色块、曲线带、贴纸元素、手绘点缀，人物是画面元素之一而非全部。**禁止「场景插画 + 叠信息卡」的偷懒结构**——用户说「没有设计感」时，问题几乎都在这里，不在角色
   - 丰富度宁可先做足：大标题、色块、贴纸、装饰元素的密度往「浓郁、夸张」做，被嫌花哨再减，比「太素」返工划算（早期海报教训）
4. **选 B 时留白区写百分比**：提示词里明确排版区位置和范围（如「左上 7%-66% 宽、7%-44% 高完全留空作后编辑排版区」）
5. **选 B 的排版实现**：用 Pillow 排入准确中文，版式结构参考：英文眉标 → 主标题错位两行 + 错版阴影 → 色块胶囊 → 编号信息块 → 描边胶囊标语。字体：macOS 的 PingFang.ttc Pillow 打不开（系统字体保护），改用 `~/Library/Fonts/` 下自行安装的开源中文字体（如阿里巴巴普惠体，Black 做标题、SemiBold 做正文）；Pillow 无原生字距，宽字距英文逐字符绘制；符号（✦ 等）可能缺字形，用多边形绘制兜底
6. **无论 A / B，文案先给用户确认再落图**

## 十、Q 版（chibi）转译规范

角色转 Q 版时身份锁依然全部生效，另加：

## 十一、生图通道（工具选择强约束）

### 0. 通道总览

| 通道 | 模型 | 适用 |
|---|---|---|
| Cursor 内置 `GenerateImage` | Image 2.5 垫图 | 在 Cursor 里工作时的默认通道 |
| 米羊网关 | `miyang/image-1`（标准档） | 没有 Cursor 内置生图时的通用通道，试构图、常规尺寸 |
| 米羊网关 | `miyang/image-hd`（高清 / 4K） | 需要 4K / 印刷级尺寸 |

网关通道需要自备 KEY，见下文。

### 1. 在 Cursor 里工作：默认用内置 GenerateImage（Image 2.5 垫图）

**在 Cursor 里，所有主生成默认走自带的 GenerateImage 工具，参考图放 `reference_image_paths`，即「Image 2.5 垫图」。** 这是第一节总原则第 4 条的落地口径，不需要跟用户确认，也不许因为「想要更大更清晰」就自己改道网关。存档 `provider` 写 `cursor.GenerateImage`。

局部修补仍可用 Gemini（第十二节），主体不许换工具重出。

### 2. 米羊网关：没有 Cursor 内置生图，或需要 4K 时

Cursor 内置工具只能选比例，实际落到 1280x720 这一档。**没有 Cursor 内置生图，或用户明确提出要 4K / 印刷级 / 喷绘尺寸时**，用米羊网关脚本 `scripts/gen_via_gateway.py`（标准档加 `--model miyang/image-1`，高清 / 4K 为默认的 `miyang/image-hd`）。使用前按顺序做三件事：

1. **查 KEY**：读仓库根 `.env` 里的 `MIYANG_API_KEY`（脚本会自己读，环境变量优先于 `.env`）。有就直接用，不要再问用户
2. **没有 KEY 就引导用户自己建**，不要代填、不要猜：请用户去 <https://miyang.cn/console/keys> 创建一把 `miyang-` 开头的 KEY，复制 `.env.example` 为 `.env` 后写进 `MIYANG_API_KEY=`。`.env` 已在 `.gitignore`，KEY 永不进仓库、永不写进 `.prompt.json`
3. **KEY 就位后再出图**，出图完仍按第六节归档，`provider` 记 `miyang-gateway`，并如实记 `model` / `endpoint` / `requested_size` / `actual_size`

### 3. 两个接口：默认垫图，文生图是少数情况

| 接口 | 用途 | 何时用 |
|---|---|---|
| `POST /api/v1/images/edits`（垫图 / 图生图，multipart） | 上传参考图 + prompt 生成新图 | **绝大多数情况**。凡画面里有角色，必须垫 `refs/` 正典参考，走这个接口 |
| `POST /api/v1/images/generations`（文生图，JSON） | 只凭 prompt 生成 | 仅无人物的纯空景 / 纹理 / 底纹。有角色而不垫图 = 角色漂移，直接算违规 |

脚本按 `--ref` 有无自动选接口：给了 `--ref` 走 edits，没给才退回 generations。多图参考时字段必须重复 `image[]`，单图用 `image`（脚本已处理）。

**模型 ID**（面向用户的公开模型名，在 `--model` 里指定）：

- 高清 / 4K 档：`miyang/image-hd`（脚本默认）
- 标准档：`miyang/image-1`（更快更省，适合试构图和普通尺寸）

### 4. 参数纪律

- `size`：长边 ≤ 3840px，两边都是 16 的倍数，长短边比 ≤ 3:1，总像素 655,360–8,294,400。常用 `3840x2160`（4K 横）、`2048x2048`（2K 方）、`1536x1024` / `1024x1536`
- `quality`：`low` 草稿 / `medium` / `high` 终稿（默认 `high`）。4K + high 单张成本按米粒计价，别拿它跑试错，构图先用 Cursor 内置工具或 `low` 试
- `output_format`：`png` 默认；`jpeg` / `webp` 更快，配 `output_compression`
- `background=transparent` 用于贴纸 / icon 抠底
- **超时至少 180 秒**（4K 常 1–3 分钟，脚本默认 read timeout 900 秒）
- 用法示例见脚本头部 docstring，提示词一律写成 UTF-8 纯文本文件用 `--prompt-file` 传，避免 shell 转义把中文提示词截断

## 十二、后期技法

- **局部修补**：以问题部位为中心裁方形工作区（约 320px）放大到 1024 送编辑接口；返回后只取目标椭圆区域羽化融回（约 10px 高斯），周围像素不变；手部修补优先 Gemini
- **比例改造**：纯色背景直接 PIL 补白；顶边有贴边元素（灯笼、彩旗）时先拼空白带，让 Gemini 外扩补画后只取回该带羽化融合；精确墙面比例生成 16:9 后按多候选窗口裁切肉眼比对
- **颜色**：需求写进生成提示词一次到位；禁止全图统计迁移滤镜（会把天空肤色一起拉偏）；必要时只做 LAB 纯色度缩放（保亮度保色相）
